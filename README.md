# 민사논증 연습실

민사소송법 사례형 시험을 **진도별**로 연습하는 무료 정적 웹앱입니다. 로그인·API 키·Node.js·유료 서버가 필요 없습니다.

## 지금 사용

- 내부 주소: **http://127.0.0.1:4192/** (서버가 켜져 있을 때)
- 다시 켜기: 이 폴더의 **start-local.cmd**를 더블클릭합니다. Python이 설치돼 있으면 서버와 브라우저를 엽니다.
- Python 없이도 **index.html**을 브라우저로 열어 사용할 수 있습니다. 기록은 각 주소·브라우저마다 별개입니다.
- 서버 종료: 실행창에서 **Ctrl+C**. 다른 프로젝트의 서버는 건드리지 않습니다.
- 포트가 사용 중이면 `python serve.py --port 4193 --open`으로 다른 포트를 선택합니다.

`127.0.0.1`은 이 컴퓨터에서만 열리는 주소입니다. 휴대폰에서 주소를 입력해 접근하는 방식이 아닙니다. 휴대폰용은 아래 GitHub Pages가 가장 간단합니다.

## 권장 공부 순서

1. 진도 하나를 고릅니다. 연도는 보조 필터이고, 첫 화면은 18개 진도 순서입니다.
2. **답안 빈칸**: 사실관계와 압축 답안을 보며 핵심 개념·요건을 채웁니다.
3. **쟁점·목차**: 필요한 쟁점만 골라 논증 순서를 구성합니다. 목차 순서는 유일한 정답으로 채점하지 않습니다.
4. **키워드 회상**: 각 목차 아래 법리·요건·사안 적용을 자신의 문장 또는 핵심어로 적습니다.
5. **통합 답안**: 목차도 보지 않고 한 답안을 완성한 후 논증 흐름을 스스로 점검합니다.

채점은 띄어쓰기·기호·등록된 동의어를 허용하고 핵심어별 부분 점수를 줍니다. **회상 확인이지 실제 시험의 법률 채점이 아닙니다.** 다른 타당한 표현을 못 알아보거나 단어 나열을 인정할 수 있으므로 답안·사안 적용을 반드시 대조하세요.

힌트·답안을 본 시도는 독립 회상 달성으로 처리하지 않습니다. 80% 이상 독립 회상은 단계 달성으로 표시합니다. 복습 간격은 낮은 점수에서 짧게, 여러 날 성공하면 길게 늘립니다. **오답·도움 회상** 필터로 즉시 재연습할 수도 있습니다.

## 자료 범위와 답안 표시

- `민사소송법 교수님` 폴더 **바로 안 사례 PDF 14개 + 정리자료 3개**를 범위로 했습니다.
- 하위 `민사소송법1·2·연습`의 중복 파일은 별도로 늘리지 않았습니다.
- 반복 설문은 한 사례로 합치고 근거 원문을 연결했습니다. 전체 연결은 **SOURCE_COVERAGE.md**에서 확인합니다.
- **자료 기반 답안**: 자료에 있는 답안·채점요지를 압축·재구성한 것. 원문 그대로의 인용 또는 교수님 작성 보증이라는 의미는 아닙니다.
- **학습용 구성답안**: 질문만 있는 자료의 답 또는 정리자료를 바탕으로 만든 연결사례. 교수님 모범답안과 구별합니다.
- 옛 추심명령 판례, 문서 추정의 단계, 일부청구 등 원문 오기·현행 판례 차이는 **주의** 및 공식 자료 링크로 구분합니다.
- 진도 분류는 학습용 순서입니다. 공식 강의 주차를 확정한 것이 아닙니다.
- 원문은 PDF 쪽수 버튼에서 봅니다. HWP는 읽기용 전사 HTML이며 서식을 재현하지 않습니다.

## 학습기록

브라우저 안에만 저장하며 서버나 외부 서비스로 전송하지 않습니다. 다른 기기·주소에서 이어하려면 **학습기록 → 기록 내보내기** 후 새 기기에서 **기록 가져오기**를 하세요. 가져오기는 기존 기록을 대체하므로 확인창이 나옵니다. 시크릿 모드·브라우저 데이터 삭제는 기록을 지울 수 있습니다.

작성 중인 빈칸·목차·키워드·통합 답안도 같은 브라우저에서 자동으로 보관됩니다. 새로고침 후 이어 쓸 수 있고, 힌트·답안을 본 사실도 유지됩니다. **작성 중 답안은 기록 내보내기 JSON에 포함되지 않고 채점기록만 이동**합니다. 새로운 독립 회상을 하려면 **빈 답안으로 새 회상**을 누르세요.

## GitHub에 올리기 — 휴대폰에서도 사용

1. **민사논증-깃헙업로드용.zip**을 풀고 그 안의 파일·sources 폴더를 사용합니다. ZIP 파일 자체를 올리는 것이 아닙니다.
2. GitHub 로그인 → 오른쪽 위 **+ → New repository** → 이름 예: `civil-case-lab` → Pages 무료 사용을 위해 **Public** → **Add a README file** 체크 → **Create repository**.
3. 저장소 **Code** 화면 → **Add file → Upload files**. 압축을 푼 폴더 **안의 내용**을 한꺼번에 끌어다 놓습니다. `index.html`이 저장소 바로 아래에 있어야 합니다. `sources` 폴더도 그대로 포함합니다.
4. 화면 아래 **Commit changes**. 기본 README를 덮어쓸 수 있습니다.
5. **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main / /(root) → Save**.
6. 배포가 끝나면 같은 화면의 **Visit site**에서 `https://아이디.github.io/civil-case-lab/` 주소를 열고 휴대폰에서도 사용합니다.
7. 수정본을 다시 올릴 때에도 **Add file → Upload files**로 같은 이름의 파일을 올린 뒤 **Commit changes**하면 Pages에 반영됩니다.

**공개 전 주의:** 업로드용 ZIP에는 원문 링크가 작동하도록 교수님 자료 PDF도 포함되어 있습니다. 공개 공유 권한이 없는 수업자료를 공개 저장소에 올리지 마세요. 로컬 이용은 그대로 가능하며, 공개 배포 권한이 있는지 먼저 확인하세요. 이 작업에서 외부에 업로드·공개한 자료는 없습니다.

업로드용 ZIP에는 실제 학습앱 파일만 들어 있습니다. `work`(OCR·검토 중간 자료), `content`, `tools`, `tests`, 다른 프로젝트와 비밀키는 제외합니다. 개발용 원본은 이 폴더에 보존됩니다.

## 개발·검사

원자료를 변경했을 때에는 추출·OCR·답안의 대조를 다시 해야 합니다. 단순히 새 PDF를 넣으면 검증 없이 자동 답안을 만들지는 않습니다.

```
python content/core_content.py
python content/summary_content.py
python tools/build.py
node tests/core.test.mjs
node tests/app.test.mjs
node tests/data-grading.test.mjs
```

빌드는 source hash·쪽수·진도·원문 연결·빈칸/정답 매칭을 검증합니다. 자료 버전은 내용 해시이므로 데이터가 바뀌면 이전 버전의 기록을 자동으로 섞지 않습니다.
