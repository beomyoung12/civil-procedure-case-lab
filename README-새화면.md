# 민사소송법 · 사례와 공통법리

## 켜기

`start-local.cmd`를 더블클릭하면 내부 주소 http://127.0.0.1:4192/ 를 엽니다.
이미 켜져 있으면 주소만 열면 됩니다. 종료는 실행창에서 Ctrl+C입니다.
Python 없이 `index.html`을 직접 열어도 작동합니다. 주소·브라우저가 달라지면 저장기록은 별개입니다.

## 세 화면

1. **반복 법리 모아보기**: 총 44개 법리 묶음을 기본 **빠른 문답** 카드로 봅니다. 질문 한 문장을 보고 답을 떠올린 뒤 **한 문장 답 보기**로 답과 구별할 점을 확인합니다. **답 모두 보기 / 답 모두 가리기**도 가능합니다. **자세한 법리 목록** 또는 각 카드의 **자세한 법리·원문**에서 기존 요건·논거·예외와 원문 답안을 그대로 확인합니다. 짧은 문답은 학습용 요약이지 원문 인용·완전한 시험 답안이 아닙니다.
2. **단원별 문제**: 기존 107개 사례분류 + 수업 설문 33개 = 기본 목록 140개입니다. 기존 18개 진도 순서를 유지하며 각 단원에 **전체 문제 수 / 중요 문제 수**를 함께 표시합니다. 중요 표시는 보라·남색, 주의사항 표시는 노란색입니다. 중요 자료만 보기도 가능합니다. 정리자료 기반 보충 8개는 별도 체크하면 포함됩니다. 진도 수는 검색·학습 여부와 무관한 해당 범위의 전체 수이고, 검색 결과 위의 수는 실제 검색·학습 필터 결과입니다. 사례분류 수는 실제 출제 횟수나 빈출 통계가 아닙니다.
3. **수업 문제**: 1~6주차 33개 설문을 14개 해당 단원별로 모았습니다. 기존 사례와 섞이지 않는 전용 화면이며 수업 주차 순 정렬도 가능합니다. 주소는 `http://127.0.0.1:4192/#classes`입니다. 중요 표시는 사용자가 요청한 수업자료 우선학습 표시입니다. 법리 화면의 **수업 연결** 수는 중요 문제 수가 아니라 수업자료가 연결된 법리 묶음 수입니다.

문제를 열면 왼쪽 학습용 문제 요지 / 오른쪽 내 답안입니다. 기존·수업 문제 모두 요지가 기본이며 **원문 문제 보기**로 교정 원문을 확인합니다. `모범답안 보기`를 누르면 오른쪽만 원문 답안으로 바뀝니다. 내 답안으로 돌아오면 작성 내용이 보존됩니다. 모바일은 문제 / 답안 탭으로 전환합니다.

작성 내용은 매 입력 때 자동 저장됩니다. 새로고침·문제 이동 후에도 이어서 쓸 수 있습니다. 저장·내보내기에서 답안과 공부표시를 파일로 보관하고 복원할 수 있습니다. 공부표시는 사용자가 직접 한 표시이며 암기완료나 법적 정확성 판정이 아닙니다. 자동채점은 이 새 화면에 없습니다.

## 원문과 학습용 안내의 구별

- 왼쪽은 기존 문제와 수업 문제 모두 **학습용 문제 요지**를 기본으로 보여줍니다. 수업 33문항도 사실관계와 물음을 따로 정리했으며 원문 인용이 아닙니다. `원문 문제 보기`를 누르면 교정된 원문 전체가 열리고, `원본·쪽별 대조`로 PDF 이미지도 볼 수 있습니다. `문제 요지로 돌아가기`로 기본 화면에 복귀합니다. 원문 답안은 요약하지 않고 유지합니다.
- **기존 107개 사례의 기본 본문은 `원자료_TXT/02_단원별`의 교정 TXT입니다.** 자료 수록 답안 101개를 연결했으며 답안이 없는 6개는 미수록으로 표시합니다. 기존 TXT의 문맥 교정본은 이미지 대조 확정 전사본이 아닙니다. 이를 수업자료의 검수 상태와 혼동하지 않도록 표시합니다.
- **수업 1~6주차 33개 설문은 `원자료_TXT/수업문제및답안_추가자료/03_문제답안_단원별`의 교정 TXT입니다.** 문제·답안 PDF 13개·46쪽을 연결합니다. 새 1주차 PDF는 문자층 없는 스캔 4쪽을 이미지로 직접 읽어 문1~5와 채점기준·각주를 전사했습니다. 명백한 중복어 2곳과 줄바꿈을 정리하고, 다음 쪽으로 이어지는 문2·문5 답안을 연결했습니다. 기존 사용자 작성 2주차 답안1 교정본과 교정 전 백업 `work/class-problems-answers-ocr/user-answer1-before-correction.txt`는 변경하지 않았습니다.
- **1주차 원문 주의:** 문제의 매매계약서·매매계약과 일부 설문·답안의 차용증서·소비대차계약 표현이 혼용됩니다. 계약 종류를 추측해 고치지 않고 TXT·사이트에 주의사항을 표시했습니다. 답안의 ‘처분문서란? 실질적 증명력이란?’ 등 채점요지 문구도 원문대로이며, 없는 답안 설명을 보충하지 않았습니다.
- 원문 답안1 제목의 ‘정의 을과 정에 대한’은 실제 상대방에 맞춰 ‘정의 을과 병에 대한’으로 고치고 메모를 남겼습니다. 확정하기 어려운 날짜·금액·판례번호와 법적 결론은 임의로 바꾸지 않았습니다. 3주차 사례1·6주차 문제2-2의 날짜 모순은 주의로 표시합니다. 4주차 문2 (2)의 수업 답안이 검토 질문만 제시한다는 점도 고지합니다.
- 선택한 답안의 TXT 연결 구간 전체를 읽습니다. 페이지가 넘어간다는 이유로 문장을 잘라 표시하지 않습니다. 첫 관할합의 사례의 ‘반면 물권적 승계인…’과 결론도 이어집니다. 본문 17px·줄간격 1.95와 목차 구분을 유지했습니다.
- 설문 경계가 미지정된 사례는 TXT에 담긴 공통 사실관계·인접 설문이 함께 표시되며 안내를 붙였습니다. 여러 출제 변형이 통합된 경우 선택한 TXT의 범위를 표시합니다.
- **원본·쪽별 대조**를 누르면 PDF 이미지·직접 추출문 뷰어로 전환합니다. **교정 TXT로 돌아가기**로 복귀합니다. 원본 PDF·이미지·옛 직접 추출문과 검수 좌표는 보존했습니다. 옛 추출문을 보는 모드에는 교정 전 자료임을 표시합니다.
- 원본 대조 화면의 **페이지 전체 보기 / 원문 확대 / 전체 PDF** 기능은 유지됩니다. 이미지의 노란 띠는 위치 안내용이며 정밀한 글자 윤곽 표시가 아닙니다.
- 반복법리 화면의 자료 발췌도 교정 TXT에서 실제 확인되는 문구로 갱신했습니다. 일반 법리 정리와 구별하며, **본문 대조**를 누르면 교정된 사례 답안을 펼쳐 해당 문단을 표시합니다. 원래 검수 발췌 데이터는 보존합니다.
- 질문만 있는 자료에 생성 답안을 모범답안으로 표시하지 않습니다. 2023년 대위소송 문항은 과거 다른 출제문제의 대조답안을 연결하고 명확히 구별합니다.
- 판례변경과 법적 결론의 교정은 별도로 표시합니다. 명백한 오타·조문 표기 교정과 법리의 변경을 혼동하지 않도록 구별합니다. 추심명령의 2025년 전원합의체 변경, 사망 시점·소송대리인, 국제적 소송경합, 문서 진정성립 등 보충에 필요한 공식 근거를 대조했습니다. 모든 현행 법령·판례를 망라한 검증은 아닙니다.
- 빈출의 기준은 이 자료에서 연결되는 사례분류 수입니다. 전국 통계나 실출제 횟수로 오인하지 않도록 표시했습니다.

## 파일 구성 / GitHub

새 화면의 실행 파일:

```
index.html
reading.css
reading.js
reading-core.js
reading-focus-core.js
reading-readable-core.js
reading-transcript-core.js
reading-class-core.js
data.js
reading-data.js
reading-source-text.js
reading-focus.js
reading-edits.js
reading-transcripts.js
reading-class-data.js
reading-quick-data.js
source-pages/        # 원문 페이지 이미지
sources/            # 원문 PDF, 정리자료 읽기용 HTML
```

`serve.py`, `start-local.cmd`는 내부 실행용이라 GitHub Pages에서는 필요 없습니다. `원자료_TXT/`, `content/`, `tools/`, `work/`, `tests/`는 내용 유지보수·검증용이며 사이트 실행에는 필요 없습니다. TXT 내용은 실행용 JS 데이터에 내장됩니다. 수업자료 추가 후에는 **새 JS 2개와 변경된 index.html·reading.js·reading.css**, 새 PDF·쪽별 이미지도 함께 반영해야 합니다.

기존 `민사논증-깃헙업로드용` 폴더와 ZIP은 **이전 버전**입니다. 새 화면을 올리려면 위 새 실행 파일을 사용해야 합니다.

교수님 문제·모범답안·정리자료 PDF, 이미지, 발췌 및 내장 텍스트를 포함합니다. **공개 업로드 허락 없이 공개 GitHub 저장소나 공개 Pages에 올리지 마세요.** 이 자료 범위가 들어간 완전한 사이트는 현재 개인용 내부 실행 기준으로 구성했습니다. 단순히 PDF만 제외해도 이미지·텍스트에 원문이 남습니다.

기존 화면을 계속 쓰려면 `legacy.html`, `styles.css`, `app.js`, `grading.js`도 함께 보관하세요. 이전 브라우저 저장키는 변경하거나 초기화하지 않았습니다.

## 유지보수

기존 수업 자료 처리 순서: `tools/correct-class-answer1.py` → `tools/build-class-answers.py` → `tools/group-class-answers.py` → `tools/build-class-website.py`.
1주차 추가·재생성: `tools/prepare-class-week1.py`(원문 이미지 준비) → `tools/import-class-week1.py` → `tools/group-class-answers.py` → `tools/build-class-website.py`.
1주차 직접 대조 전사본·교정 목록: `content/class-week1.json`. 가공기록: `원자료_TXT/수업문제및답안_추가자료/1주차_가공기록.json`. 앞선 문제·답안 OCR은 다시 실행하지 않습니다.
수업 문제·법리 연결: `content/class-website-map.json`. 원문 문구는 바꾸지 않고 단원·법리·발췌 문단 위치를 별도로 관리합니다.
수업의 학습용 문제 요지: `content/class-study-summaries.json`. 원문 TXT·전사 데이터와 분리하며, 웹 빌드 때 전체 문항의 누락 여부와 입력 파일 해시를 검사합니다. 별도의 실행용 JSON 업로드 없이 `reading-class-data.js`에 내장됩니다.
수업 웹 확장: `reading-class-data.js`, `reading-class-core.js`. 기존 데이터·저장키·ID는 변경하지 않습니다.
수업 검증 기록: `원자료_TXT/수업문제및답안_추가자료/문제답안_가공기록.json`, `2주차답안1_교정기록.json`, `work/class-website-build-report.json`.

현재 기본 본문: `원자료_TXT/02_단원별/*.txt`
교정 TXT 웹 데이터 생성: `tools/build-website-transcripts.mjs` (기존 교정 기록의 파일 해시와 일치해야 실행)
발췌 구간 보정: `content/website-quote-selections.json` (현재 TXT의 명시적인 시작·끝 문구)
생성 결과: `reading-transcripts.js`, `work/website-transcript-report.json`
표시·자료 선택: `reading-transcript-core.js`
TXT 자체와 아래 옛 원본 대조용 데이터는 별도로 보존합니다. 원본 대조 빌더만 다시 실행해도 교정 TXT가 덮어써지지 않습니다.

반복 법리 연결: `content/law-groups.json`
일반 법리 보충: `content/law-guides.json` (원문과 별도)
빠른 문답: `content/law-quick-checks.json` (44개, 학습용 요약·구별할 점·기존 법리 근거 필드를 별도 관리)
빠른 문답 웹 데이터 생성: `node tools/build-quick-laws.mjs` → `reading-quick-data.js`. 모든 기존·수업 추가 법리의 수록 여부와 근거 필드를 검사합니다.
문제·답안 선택 구간: `content/source-focus.json` (정확한 텍스트 경계 또는 검토한 이미지 좌표)
원문 표시 데이터 생성: `tools/build-reading.py`
구간·형광표시 생성: `tools/build-source-focus.py` (앞 빌더 이후 실행)
읽기용 교정 내역: `content/source-edits.json` (PDF·쪽·정확한 원문 위치·교정 근거)
교정 데이터 생성: `tools/build-readable.mjs` (위 빌더들 이후 실행)
문단·목차·띄어쓰기 표시: `reading-readable-core.js` (원본 데이터와 분리)
원문 PDF·직접 추출 텍스트 및 검수 인용: 기존 `data.js`, `work/extracted/`, `sources/`
원문 페이지 이미지: `source-pages/`

빌더는 원본 PDF SHA-256을 대조하고 모든 관련 페이지 범위를 검사합니다. 텍스트는 직접 PDF 추출만 사용하고 선택된 문자열의 SHA-256도 저장합니다. 원본 매핑을 덮어쓰지 않고 누락된 다음 페이지를 보충합니다. 생성 결과는 `work/reading-build-report.json`, `work/focus-build-report.json`에 저장합니다. Node 자동 검사는 `node --test tests/*.test.mjs`로 실행합니다.
